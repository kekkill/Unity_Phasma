# Журнал улик

Ветка: feature/evidence-journal. Сцена для проверки: Assets/Scenes/RoomSearchPrototype.unity. В Prototype журнал тоже подключён; ссылки вручную назначать не нужно.

## Что добавлено

J открывает и закрывает журнал; Esc и кнопка «Закрыть» тоже закрывают его. Во время заполнения игрок не ходит, не вращает камеру, не взаимодействует и не использует/бросает/устанавливает предметы. Текущая поза приседания сохраняется, гравитация продолжает действовать. Открытие отменяет предпросмотр установки, освобождает курсор. Мир и охота продолжают действовать; удерживаемый исправный крест сохраняет защиту. Смерть закрывает журнал и освобождает курсор для экрана завершения раунда.

Четыре ручные отметки: минусовая температура, EMF, ультрафиолет и записи в книге. Для каждой доступны «Не проверено», «Есть», «Исключено». Не проверенная улика не влияет на список. Подтверждённая требует её наличия в профиле, исключённая — отсутствия. Событие может ещё не произойти: отсутствие записи/следа в данный момент не доказывает отсутствие улики.

Добавлены ручные наблюдения о соли (обходит вне охоты / оставляет следы / игнорирует) и исправном кресте (отпугнул / игнорирует). Они также фильтруют кандидатов по действующим правилам профилей. Наблюдение о кресте делайте только с исправным предметом в зоне защиты; бросание и установка — разные состояния.

Справочник содержит три условных названия существующих типов:
- Обычный призрак → RoomSearchTestProfile.
- Следопыт → FootprintGhostProfile.
- Неуязвимый к кресту → CrossImmuneGhostProfile.

Это названия для тестового каталога, не окончательный список типов. Все текущие профили поддерживают все четыре улики; их комбинации не менялись в этом этапе. Поэтому положительные отметки этих улик пока не разделяют типы, а исключение любой из них убирает все три. Разделить текущие типы можно наблюдением о соли и кресте. Будущие разные комбинации можно задавать в GhostProfile: фильтр читает те же флаги, которыми пользуются игровые системы.

Можно выбрать подходящий тип как итоговую версию. Если последующие отметки исключат его, выбор сохраняется с предупреждением о противоречии. Журнал не подменяет версию автоматически. Выбор и отметки сохраняются при закрытии и смерти в текущем раунде; «Начать заново» создаёт чистый журнал. «Снять выбор» убирает только версию, «Очистить журнал» сбрасывает всё. Завершение успешной миссии, сравнение версии с настоящим призраком, награды и сохранение между запусками — следующий отдельный этап.

Отметки заполняются игроком. Журнал не читает активного GhostController и не раскрывает выбранный игрой тип; он сравнивает заметки с общедоступным каталогом. Автозаполнение при обнаружении прибором пока не добавлено. EMF здесь соответствует существующему общему флагу активности: отдельная улика EMF-5 ещё не реализована, уровни активности сейчас 2–4. Солёные следы — наблюдение о поведении, не автоматически УФ-улика.

## Компоненты и настройки

- Player → JournalState: личные отметки, наблюдения и ID итоговой версии. Catalog уже назначен.
- Player → PlayerJournalController: открытие, блокировка управления, курсор и закрытие при смерти.
- Player → JournalScreen: прокручиваемый интерфейс; на узком Game View колонки располагаются друг под другом.
- Assets/GhostProfiles/PrototypeJournalCatalog.asset: ID, названия, описания и ссылки на профили. ID должны быть непустыми и уникальными; описание следует обновлять при изменении правил типа.
- GhostProfile.HasEvidence использует существующие поля профиля; настройки агрессии, креста, соли и генерации улик сохранены.

Данные находятся на отдельном JournalState каждого игрока. Catalog — общий справочник. Изменения вызывают Changed; выбор хранится как стабильный ID каталога. PlayerInputReader блокирует только собственные игровые действия и учитывает владельцев блокировки. Реального сетевого обмена нет: будущий мультиплеер потребует решения о личных/общих отметках, владельце ввода и репликации выбора.

## Проверка в Unity

1. Подтяните ветку целиком, дождитесь компиляции Unity. Откройте RoomSearchPrototype и запустите Play Mode.
2. В верхнем меню выберите **Phasma → Validate Journal (Play Mode)**. Ожидается `Journal validation PASSED` с количеством проверок. Временные профили имеют разные комбинации улик, поэтому тест проверяет реальные положительные/отрицательные фильтры всех четырёх улик, неизвестное состояние, реакции на соль/крест, отсутствие кандидатов, выбор и противоречия. Проверяется также настоящий каталог, независимость заметок/блокировки двух локальных участников, отмена установки, закрытие при смерти и сброс. Временные объекты удаляются, исходные профили не изменяются. Это локальная проверка модели и управления, не сетевой тест и не автоматический тест рисования/кликов интерфейса.
3. Нажмите J. Кликайте отметки; выберите «Соль → Оставляет следы»: должен остаться Следопыт. Выберите его, закройте и снова откройте журнал: заметки и версия сохраняются.
4. Поменяйте соль на «Игнорирует»: должен подходить Неуязвимый к кресту, а старая версия должна остаться с предупреждением. Отметьте крест «Отпугнул»: подходящих типов не останется. Верните наблюдения в «Не проверено»: снова доступны все три. Проверьте «Снять выбор» и «Очистить журнал».
5. При открытом журнале попробуйте WASD, мышь, E/F/G/R, Shift/Ctrl. Игровые действия не должны выполняться. Закройте J/Esc/кнопкой: управление должно вернуться, закрытие не должно использовать предмет. Откройте из приседа: поза сохраняется. Откройте во время предпросмотра установки: предпросмотр исчезает. Проверьте интерфейс в небольшом Game View, прокрутку и клики по всем кнопкам.
6. Во время охоты откройте журнал: призрак продолжает движение. Дайте ему убить игрока без защиты: журнал должен исчезнуть, кнопка «Начать заново» должна работать, новый журнал — пустой.
7. Повторите Phasma → Validate Defensive Items (Play Mode) и Validate Death and Round (Play Mode); вручную проверьте крест, соль, обычную установку, подбор/бросание и движение после закрытия журнала.

В облаке проведены проверки синтаксиса C# и ссылок/метаданных сцен/каталога/ввода, а также статической геометрии. Unity Editor отсутствует: компиляция, эта проверка и ручная работа интерфейса здесь не запускались. Успешный результат предыдущего этапа защитных предметов не заменяет проверку журнала и его влияния на управление.
