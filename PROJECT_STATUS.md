## Implemented systems
- Player movement/look/crouch/sprint, per-participant input action instances, interaction UI and a three-slot personal inventory with one selected item in hand.
- Rooms/temperature, doors/lights, EMF/UV/writing evidence and motion sensor.
- Ghost profile, vision/hearing/memory, anger, probabilistic hunts, chase and room search.
- GhostNavigation owns NavMesh movement; RuntimeNavigationWorld explicitly bakes floor/walls and gives the moving door a carving obstacle. Three connected zones: Bedroom ↔ Corridor ↔ Kitchen. Corridor is not a home ghost room. Roaming stays in a room; room transitions use physical openings. Blocked/stalled transitions fall back to reachable local search; Hunts now open physically reachable nearby closed doors; normal blocked-path recovery is retained.
- Alive/Dead state, local participant registry, dead-target filtering, presentation/control disabling, line-of-sight attack, all-dead completion and restart. These are local foundations, not networking or voice transport.
- Defensive items (feature/defensive-items): Dropped/Held/Placed item states, all child colliders disabled while held, R/F placement preview, placed-only writing book/motion sensor. Cross protects in hand and when placed nearby, saves the breaking attack, breaks by profile/anger, repels hunting and supports immune types. Salt container (5 portions) places piles with profile-specific avoidance/scattering/footprints/ignore rules and dynamic Salt NavMesh area updates. Optional cyan ghost debug silhouette can be hidden in Inspector.
- Both gameplay scenes include placement, debug visual, salt reaction and a primitive defensive-item setup. The old Interaction-blocking ProtectionWard is preserved but inactive. Example FootprintGhostProfile and CrossImmuneGhostProfile are supplied alongside existing profiles.
- Evidence journal (feature/evidence-journal): personal JournalState, manual Unknown/Confirmed/Excluded notes for four evidence types, salt/cross observations, public three-type catalog, profile-based filtering and stable-ID final choice. J opens, J/Esc/button closes. JournalScreen is a scrollable local UI; PlayerJournalController owns cursor/input blocking and death cleanup. Both scenes are wired. Choices survive contradictory later notes with a warning. Notes survive closing/death during the round and reset on scene restart. Opening cancels placement; crouch posture is preserved; world/hunts continue. Gameplay blocking is per input instance with multiple owners and a close-frame guard.

- Mission loop (feature/mission-loop): uniform random catalog profile chosen once in Awake, with Manual mode for testing; preparation/investigation/ended phases; blue safe annex with start equipment and a physical entrance into Corridor; ghost perception/attack safety checks and annex excluded from navigation; E extraction terminal requiring all surviving local participants to return and select a known journal type; immutable actual-type/per-player results, correct/wrong outcome, all-dead outcome and restart. PlayerMissionPresentation owns local end-of-mission controls/menu cleanup. The earlier Prototype scene retains its old layout/manual profile/death-only completion.

- Salt-contact batch (feature/salt-contact-feedback): physical foot overlap and bounded swept contact queries; persistent first-step imprint on intact salt; separately expiring six-step trail; unchanged profile-specific ignore/avoid/hunt-scatter rules. SaltPile keeps first imprint pose/state, SaltContactArea defines the thin physical proxy, GhostSaltContactSensor detects contact, GhostSaltReaction chooses the rule, SaltPileVisual displays pile/imprint, SaltFootprintTrail displays temporary steps. Both scenes explicitly wire sensor/trail. Marking changes appearance only and does not rebuild the navigation area. Scattering hides the intact imprint but preserves historical stepped state.

- Latest batch (feature/three-slot-inventory): three per-participant slots, 1/2/3 selection, E pickup into selected-empty/first-free slot and immediate equip, G selected-item drop (original binding restored after user feedback), read-only HUD with item names/empty slots and salt/broken-cross status. Stored equipment is inactive while keeping component state; only selected/placed cross protects. Placement removes the selected item, salt pouring keeps the container, selection cancels preview and consumes same-frame item actions. Journal/closing frame, death and mission end guard commands. Death drops all slots before hiding the player; exclusive local ownership prevents another participant picking held/stored items. Both scenes explicitly wire inventory/HUD, preserving hold-point references and serialized enum values. See Docs/INVENTORY_CHECK.md.
